# 赛题要求对照

本文把赛题三、评分标准逐条落到本项目，明确「已交 / 部分 / 缺」。
量化数据与证据见 [TEST_REPORT](TEST_REPORT.md)，方案见 [ARCHITECTURE](ARCHITECTURE.md)。

## 1. 六项硬性交付

| # | 赛题原文要点 | 本项目 | 证据 |
|---|---|---|---|
| 1 | MIPI CSI 驱动 IP，至少单路 1080P@60fps，鼓励 4K@30 | **4K30 已交**；无 1080p60 模式 | 3840×2160@29.9 fps、丢组 0（TEST_REPORT §3） |
| 2 | FPGA ≥3 种预处理，AXI-Stream 流水线 | **已交**（类 AXI-Stream） | 灰度/高斯/HE/Sobel 四路并行，1920×1088@30 fps（§4） |
| 3 | JPEG/LZ77 硬件压缩，压缩率 ≥30%，画质/码率对比 | **已交，非实时** | 95.5%，65.7 ms/帧，PSNR 34.9 dB，q 扫描表（§5） |
| 4 | PCIe（3.0 优先）稳定传压缩帧，端到端 ≤50 ms | **部分**：Gen2×2 稳定传压缩帧；传输段 <1 ms；端到端（SOF→主机拿到压缩帧）≈118 ms | §6，口径已写明 |
| 5 | RK3588 NPU 本地推理，结果回显/叠加 | **已交** | YOLO11n INT8 40~45 ms/帧，叠加图（§7） |
| 6 | 帧率/延迟/资源/压缩率/推理耗时/整机功耗 | **部分**：前五项有数，功耗未测 | §8，功耗需外接功率计（板上无电流传感器） |

## 2. 「FPGA 内自主实现」约束

采集、预处理、压缩、PCIe 推帧均在 PH1P100 RTL 内完成；RK3588 只承担取流、
显示、NPU 推理与网络，没有用上位机替代核心链路。

| 环节 | 实现位置 |
|---|---|
| MIPI CSI-2 接收/校验 | `fpga/rtl/ep_side/cam/`、`rtl/checked/` |
| 预处理三算法 | `fpga/rtl/ep_side/img/algo/` |
| JPEG 编码 | `fpga/rtl/ep_side/codec/` |
| PCIe 端点/推帧 | `fpga/rtl/ep_side/pcie_ep_engine.v`、`ddr_frame_pusher.v` |
| NPU 推理/叠加 | `display/src/detect/` |

## 4. 发挥创新拓展项

| 方向 | 现状 |
|---|---|
| 多通道采集 | 双路 1080p 同步已测；4 路、双路 4K 未做 |
| 高级预处理 | 边缘检测（Sobel，硬件 4 路并行之一）已做；HDR/形态学/亚像素未做 |
| 高性能压缩 | 固定 q；无自适应码率、无彩色 |
| 异构传输优化 | one-shot + 乒乓缓冲已做；无 MSI、无流式推帧 |
| AI 多任务 | 单模型多类；无跟踪/测距/分级 |
| 网络/存储/远程 | display HTTP 实时页；无 SD 录制/4G |
| 工程化/低功耗 | 1 h 压缩长稳；无宽温/功耗数据 |

## 5. 距提交还缺什么

| 优先级 | 事项 | 现状 | 建议 |
|---|---|---|---|
| P0 | 整机功耗 | 未测 | USB-C PD 表/台式电源，待机/4K/JPEG/NPU 四态 |
| P0 | 端到端 ≤50 ms | ≈118 ms | EOF 时间戳；三缓冲/流式推帧 |
| P1 | 1080p60 | 未实现 | 加 1080p60 寄存器表，或书面说明 4K30 替代 |
| P1 | 4K+JPEG 同一位流 | 两个位流 | 4K ROI 压缩；编码器需 >30 fps |
| P1 | 动态码率/彩色 JPEG | 固定 q、灰度 | 量化表可配 + 彩色分量 |
| P2 | 双路 4K、4K 同步、MSI、故障注入 | 未做 | 打包节拍/板级 XVS 飞线/中断路径 |
| P2 | mAP、多目标跟踪、SD 录制 | 未做 | 按答辩演示取舍 |

## 6. 一句话结论

六项硬性要求中，2/3/5 完整，1 以 4K30 覆盖像素吞吐但缺 1080p60 时序，
4 的 ≤50 ms 只在传输段成立，6 缺整机功耗。工程与文档已收敛，剩余是
**功耗测量**与**压缩链路实时化**两件硬仗。
