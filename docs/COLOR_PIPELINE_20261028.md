# 彩色链路与相位结论（2026-10-28）

本文记录当前 R10F 帧从 Bayer 到彩色 JPEG 的完整口径，以及“为什么是 RGGB”。
它是 `display/README.md` 与 `docs/DATAFLOW.md` 的颜色部分的上游依据；发现新证据时先改这里。

## 1. 数据事实

| 项 | 值 |
| --- | --- |
| 交付格式 | R10F v1，非压缩 packed RAW10 |
| 几何 | 1920×1080 ROI，stride 2400 B/行 |
| 传输 | 128 B 头 + 2,592,000 B 载荷 + 640 B 尾零 = 2,592,768 B |
| 8bit 预览 | 每个 10bit 采样的高 8 位（与 `frame_grab` 的 PGM 一致） |
| 黑电平 | 8bit 12（10bit 50 >> 2） |
| 头 0x28 | 写 3(GBRG)，但由 `SRC_BAYER_PHASE=0` 占位和 ROI 奇偶推导，**不是测量值** |

## 2. 链路

~~~mermaid
flowchart LR
  R["R10F packed RAW10<br/>1920x1080"] --> U["解包 5B/4px<br/>取高 8 位"]
  U --> D["去马赛克<br/>当前 RGGB"]
  D --> B["扣黑 12"]
  B --> W["灰世界 AWB<br/>排除 max>=250"]
  W --> A["AE 只提亮"]
  A --> G["gamma 2.2 LUT"]
  G --> H["高光去饱和"]
  H --> J["JPEG / HTTP"]
~~~

## 3. 相位：先定“绿在哪条对角线”

frame A 的 2×2 原始均值：

~~~text
(0,0)=31.32  (0,1)=56.72
(1,0)=56.68  (1,1)=35.85
~~~

- 两条绿对角只差 0.07%；主对角差 13.5%。
- 马赛克里只有绿占两格 → 绿在反对角 `(0,1)/(1,0)`。
- 因此只可能是 **RGGB** 或 **BGGR**；`GBRG`/`GRBG` 会出品红/绿棋盘，直接排除。

## 4. R/B 归属：当前取 RGGB

同一间办公室同时被 A/B 两路看到，告示牌是天然的同场景参照：

| 相位 | A 路告示牌 | B 路告示牌 |
| --- | --- | --- |
| RGGB | 黄色 | 黄色 |
| BGGR | 蓝色 | 蓝色 |

同一块牌子不可能既黄又蓝。当前安装下只有 RGGB 让两边一致；用户对 A 路
`--bayer rggb` 的结果也确认“有点对”。因此 `--bayer auto` 当前解析为 **RGGB**。

### 反方证据 / 风险

- 早期材料（`bayer_phase_wb_compare.png`、旧 RGB565 路径）给过 BGGR；那些来自
  180° 翻转的旧预览或另一套安装，不能直接搬到当前帧。
- R10F 头 0x28=3 是占位值，任何“按头字段解”的做法都会错。
- 换模组、改支架、改 MIPI 走线、改 ROI 奇偶（X0/Y0/SKIP_ROWS）后，R/B 可能翻转。
  必须用**已知色卡/已知颜色物体**重测；显式 `--bayer rggb|bggr` 可覆盖。

## 5. 白平衡与色调

当前 `--auto`（device/r10f 默认开，`--no-auto` 可关；synthetic/pgm 仍要显式开）：

1. 扣黑 12；
2. 灰世界 AWB，排除 max>=250 的过曝像素（灯管），R/B 相对绿求增益，夹 0.25..4.0，
   EMA 0.35 平滑；
3. AE 目标 100，但 **只提亮不压暗**（固定曝光传感器压暗只会白丢动态范围）；
4. gamma 2.2；
5. 高光去饱和：输出 max>220 向亮度混合，最多 85%，压掉灯管品红/绿边；
6. 4×4 有序抖动。

### 为什么不再用旧的固定 2400/2062

旧增益会让白墙偏米黄、标志偏橙、告示牌偏紫；在本帧上实测白墙色度误差明显大于
扣黑后的灰世界。固定增益只适合特定光照，当前默认改为逐帧灰世界。

### 为什么“绿衣服”可能仍然不绿

这两帧里前景织物与白墙的相机色度几乎相同（差异 <2%）。任何让白墙变白的全局 AWB
都会把它还原成中性；要保留绿色只能把白墙也染绿，或做按区域/语义的白平衡。
这是当前像素的事实，不是相位错。需要确认请拿已知色卡/已知颜色物体重拍。
